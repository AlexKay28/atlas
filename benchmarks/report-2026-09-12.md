## Honest caveats

- Wall times are real measurements and vary run to run and machine to machine; the report publishes mean with min..max spread over repeated trials.  Counts (events, tasks, dispatches, envelope bytes) are deterministic.
- SCATTER/GATHER fan-out drives the sequential plan loop by contract (candidate-order semantics), so width gives it no latency gain: this is the measured 'where parallel execution is NOT faster' data point, not a harness defect.
- Fine-grained phase telemetry (queue/startup/worker/join split, peak concurrency, token/usage accounting, retries and cancellation waste) requires live-model runs and is recorded as unknown here; zero-valued usage placeholders are never presented as measurements.
